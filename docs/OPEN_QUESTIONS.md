# Открытые вопросы Clipensk

Этот файл содержит только ещё не зафиксированные решения. Утверждённые требования находятся в `REQUIREMENTS.md`, техническая архитектура — в `ARCHITECTURE.md`.

## 1. Конкретная Open Source-лицензия

Зафиксировано: проект полностью Open Source.

Не выбрано:

- MIT;
- BSD-3-Clause;
- MPL-2.0;
- GPL-3.0-or-later;
- другой вариант.

## 2. Точная версия Windows App SDK / .NET на старте реализации

Зафиксировано:

- WinUI 3;
- Windows App SDK Stable;
- C#/.NET.

Перед созданием solution необходимо выбрать конкретные версии SDK/runtime и минимальную поддерживаемую версию Windows.

## 3. Финальная схема распространения

Нужно определить:

- MSIX как основной способ установки;
- unpackaged/portable вариант;
- нужны ли оба варианта.

Для MSIX уже зафиксировано, что при первом запуске пользователь выбирает каталог хранения данных.

## 4. Криптографическая конфигурация

Зафиксировано:

- один MasterKey для всех защищённых БД;
- пароль не сохраняется;
- Argon2id — базовый кандидат KDF;
- SQLCipher — базовый кандидат шифрования SQLite.

Нужно выбрать:

- точные параметры Argon2id;
- точный способ передачи raw MasterKey в SQLCipher;
- параметры SQLCipher;
- политику очистки чувствительной памяти;
- процедуру смены пароля и/или MasterKey.

## 5. Hot backup / snapshot

Сознательно отложено.

Пока сохраняется требование, что файлы должны быть доступны стороннему процессу для открытия на чтение/копирования «на лету». Окончательный протокол получения гарантированно согласованной резервной копии будет определён отдельно.

## 6. Набор форматов и лимиты по умолчанию

Нужно утвердить конкретные defaults:

- какие текстовые форматы включены при новой установке;
- лимит Plain/Unicode Text;
- лимит HTML;
- лимит RTF;
- лимиты изображений;
- лимиты explicitly enabled custom binary formats;
- ограничения `CF_HDROP` по количеству элементов/размеру текстовой записи.

Уже зафиксировано:

- HTML и RTF хранятся только в БД;
- изображения — external files;
- unknown registered/private binary payload выключен по умолчанию;
- CF_WAVE, CF_RIFF и virtual file contents не сохраняются.

## 7. Период журнала по умолчанию

Механизм зафиксирован, но конкретное значение (например 7/30/90 дней) пока не выбрано.

## 8. Параметры ротации архивов по умолчанию

Нужно определить начальные значения:

- maximum record count;
- maximum physical database size;
- maximum calendar span;
- ANY/ALL логика включённых условий.

## 9. Storage calendar time zone

Нужно окончательно определить политику временной зоны, относительно которой событие относится к календарному дню архива:

- фиксированная time zone, назначенная хранилищу;
- локальная Windows time zone на момент события с сохранением offset/time-zone identity;
- иной вариант.

Требование неизменно: один календарный день не может принадлежать двум архивам.

## 10. Формат файлов изображений

Нужно определить, сохраняется ли:

- оригинальный clipboard representation без преобразования;
- нормализованный PNG;
- иной вариант в зависимости от исходного формата.

SHA-256 считается от точных физически сохранённых байтов.

## 11. Формат файлов локализации

Предварительно предлагается JSON, но окончательный schema/versioning ещё не утверждены.

Нужно определить:

- точную JSON-схему;
- правила совместимости версий;
- подпись/проверку сторонних переводов, если потребуется;
- команду экспорта шаблона перевода.

## 12. Поведение Quick History и вставки

Нужно детализировать:

- глобальные горячие клавиши по умолчанию;
- режим «скопировать выбранную запись обратно в clipboard»;
- режим автоматической вставки в исходное окно;
- focus restoration;
- plain-text paste;
- обработку приложений с ограничениями foreground activation.

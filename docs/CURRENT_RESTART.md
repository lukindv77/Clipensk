# «Начать текущую базу заново» при потере `current.db`

Статус: **реализовано** (решение пользователя 2026-09-23, `OPEN_QUESTIONS.md` §4 п.3):
`ProtectedStorageDatabaseService.StartCurrentAnewAsync` (шаги 2–3), `ProtectedCurrentRestartService`
(шаги 3–5), кнопка «Начать текущую базу заново…» на экране разблокировки
(`JournalWindow.CurrentRestart.cs`). CI на `c480494`: Build run `35855767529`, Native run
`35855769935` — SUCCESS. Ручной smoke на Windows — `UNVERIFIED`.

## 1. Когда применяется

`Current/current.db` отсутствует, а другие базы хранилища есть (`Current/storage-catalog.db` и/или
`Archive/archive_*.db`). Обычная разблокировка в этом состоянии отказывает
(`MissingOrPartialStorage`), и сама она ничего не создаёт: новую `current.db` создаёт только это
явное действие с подтверждением.

Повреждённая, но существующая `current.db` сюда не относится — действие её не трогает и отказывает.

## 2. Что пользователь теряет и что остаётся

Current хранит правила сбора (глобальная политика, группы приложений и их политики), identity
приложений, настройки пользовательских форматов, незавершённые операции и свежую историю, ещё не
перенесённую в архив. Catalog источником истины не является.

- **Остаётся:** все архивы — они по-прежнему в журнале (у каждого архива своя копия identity
  приложений, поэтому имена приложений в старых записях сохраняются); внешние файлы архивных
  записей; `StorageId`, соль и пароль хранилища.
- **Теряется:** записи Current, правила сбора, группы, настройки пользовательских форматов,
  незавершённые операции Current (их marker'ы жили в Current). После действия Clipensk, как при
  новом хранилище, просит заново задать правила сбора.

## 3. Протокол

Выполняется до сессии, как восстановление Catalog: пароль введён, Clipensk заблокирован.

1. **Ключ и `StorageId`.** Ключ выводится из пароля по соли из заголовков уцелевших баз;
   `StorageId` — из `DatabaseIdentity` первой базы, открывшейся этим ключом
   (`CRYPTOGRAPHY.md` §4). Неверный пароль — отказ, ничего не создаётся.
2. **Предусловия** (перепроверяются в сервисе): `current.db` отсутствует; хотя бы одна база
   хранилища есть и открывается этим ключом с тем же `StorageId`.
3. **Новая `current.db`.** Создаётся во временном файле `Current/.clipensk-current-restart-<id>.tmp`
   (тот же ключ и соль хранилища, тот же `StorageId`, новый `DatabaseId`, текущая схема), проверяется
   штатной проверкой и публикуется переименованием без замены. Появившаяся к этому моменту
   `current.db` — отказ; временный файл удаляется.
4. **Catalog перестраивается** из новой Current и архивов: отсутствующий — восстановлением
   отсутствующего Catalog, существующий — заменой с сохранением прежнего в
   `Current/CatalogQuarantine` (`STORAGE_CATALOG_RECOVERY.md`).
5. **Штатная проверка пары** Current + Catalog. После этого пользователь разблокирует Clipensk
   обычным образом.

## 4. Сбои

- До шага 3 — ничего не изменено.
- Сбой между публикацией `current.db` (шаг 3) и перестроением Catalog (шаг 4):
  - Catalog отсутствует — обычная разблокировка отказывает (`MissingOrPartialStorage`), на экране
    разблокировки доступно восстановление Catalog;
  - Catalog прежний — пара проходит проверку: прежний Catalog лишь ссылается на внешние файлы
    записей утраченной Current (файлы дольше не уходят в корзину), описание архивов в нём верно.
    Кнопка «Проверить / восстановить storage-catalog.db» перестраивает его.
- Сбой перестроения Catalog (например, несогласованный набор архивов) не откатывает созданную
  `current.db`: она пуста и корректна, а состояние сводится к одному из двух предыдущих.
- Staging прерванной ротации или разделения архивов (`Archive/.clipensk-archive-rotation-*`,
  `Archive/.clipensk-archive-split-*`) не удаляется: их marker'ы жили в утраченной Current, и
  довести их некому, но прерванное разделение может держать в staging единственную копию части
  истории. Такой staging остаётся как есть и блокирует смену пароля (`PASSWORD_CHANGE_PROTOCOL.md`
  §6), пока его не разберут вручную.
- Временный файл `Current/.clipensk-current-restart-*.tmp`, оставшийся после аварийного завершения
  процесса, ни на что не влияет: он не является базой хранилища (`StorageDatabaseFiles`) и
  разблокировкой не открывается.

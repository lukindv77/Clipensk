# Резервная копия хранилища и открытие хранилища из папки

Статус: **реализовано** (этапы 1–3, §5): `DataRootBackupService`, `DataRootOpenService`
(Infrastructure), «Настройки» → «Хранилище» → «Создать резервную копию…» и «Открыть хранилище из
папки…» (`JournalWindow.DataRootBackup.cs`). Ручной smoke на Windows — `UNVERIFIED`. Решение пользователя 2026-09-23 (`OPEN_QUESTIONS.md` §5): вариант 1 — ручная
копия с блокировкой, вместе с действием «Открыть хранилище из папки…» для восстановления. Горячая
копия без блокировки и автоматические копии не выбраны.

## 1. Что такое резервная копия

С решения 2026-09-23 хранилище — это только файлы каталога данных: базы (соль хранилища в заголовке
каждой, `CRYPTOGRAPHY.md` §3) и внешние файлы. Поэтому резервная копия — побайтная копия всего
дерева каталога данных, такая же, как цель переноса (`DATA_ROOT_RELOCATION_PROTOCOL.md` §2):
`Current/`, `Archive/` (включая staging незавершённых операций), `Files/`, `Trash/`, `Languages/`,
карантин Catalog. Ключ не нужен: содержимое баз не расшифровывается и не переписывается.

- Копия открывается паролем, который действовал в момент её создания; смена пароля позже копию не
  меняет (`PASSWORD_CHANGE_PROTOCOL.md` §6).
- Внешние файлы (`Files/`, `Trash/`) по проекту не шифруются — в копии они тоже открыты. Папку копии
  Clipensk закрывает от других пользователей Windows так же, как каталог данных
  (`WindowsDataRootProtectionService`), но при переносе копии на другой носитель это теряется.
- `settings.json` (рядом с `Clipensk.exe`) в каталог данных не входит и в копию не попадает:
  горячая клавиша, правила интерфейса и подсказка к паролю остаются настройками программы.

## 2. Инварианты

1. **Каталог данных не меняется.** Копия ничего в нём не создаёт, не удаляет и не переписывает;
   настройки (`DataRootPath`) не меняются.
2. **Никаких открытых соединений во время копирования.** Как перенос: Clipensk заблокирован (сам
   блокируется перед копией), каждый файл источника открыт эксклюзивно (`FileShare.None`) до конца
   проверки; занятый файл — отказ до любой записи.
3. **Проверка.** Каждый скопированный файл перечитывается и сверяется с источником по размеру и
   SHA-256; дерево копии должно совпадать с манифестом источника без лишних записей.
4. **Готовая копия узнаётся по имени.** Копия пишется в папку `Clipensk-backup-<дата>_<время>.incomplete`
   и только после проверки переименовывается в `Clipensk-backup-<дата>_<время>` (переименование каталога
   в том же родителе атомарно). Папка без суффикса `.incomplete` — всегда полная проверенная копия.
5. **Удаляется только своё.** При отказе или отмене удаляются только файлы и каталоги по манифесту и
   временные файлы копирования в папке `.incomplete`, затем она сама, если пуста.

## 3. Создание копии

«Настройки» → «Хранилище» → «Создать резервную копию…». Пользователь выбирает папку `P`; копия —
новая подпапка `P\Clipensk-backup-yyyy-MM-dd_HH-mm-ss` (местное время начала).

**Предусловия** (до любой записи):

- нет незавершённого переноса (marker в `settings.json`);
- каталог данных настроен, существует, не ссылка, в нём есть хотя бы одна база хранилища;
- `P` существует, это каталог, не ссылка; `P` не совпадает с каталогом данных и не лежит внутри него
  (иначе копия попала бы в следующую копию); ни итоговая папка, ни `.incomplete` ещё не существуют;
- дерево каталога данных без ссылок и без имён, различающихся только регистром (манифест переноса);
- свободного места на томе `P` не меньше размера каталога данных плюс запас (5 %, не менее 64 МБ).

**Шаги:**

1. Окно подтверждения: откуда, куда, сколько файлов и данных, свободное место; Clipensk будет
   заблокирован, после копии пароль вводится снова; копия откроется паролем, действующим сейчас.
2. Clipensk блокируется (если разблокирован), как перед переносом.
3. Манифест каталога данных и эксклюзивные дескрипторы всех файлов (занято сразу после блокировки —
   повтор до шести раз с паузой 0,5 с, как у переноса).
4. Создаётся папка `.incomplete`, к ней применяется защита доступа (до первого байта).
5. Копирование по манифесту во временные имена `*.clipensk-relocating` с переименованием, SHA-256.
6. Проверка (инвариант 3). Последняя точка отмены.
7. Папка `.incomplete` переименовывается в итоговую. Дескрипторы источника освобождаются.
8. Итог: путь копии, число файлов и объём; если файловая система не поддерживает защиту доступа —
   предупреждение.

**Отказ или отмена** до шага 7 — удаление папки `.incomplete` по инварианту 5; если удалить не
удалось, сообщение называет её путь. **Аварийное завершение процесса** оставляет папку
`.incomplete`: Clipensk её не отслеживает (marker'а нет, каталог данных не менялся), по имени видно,
что копия не завершена, «Открыть хранилище из папки…» её не принимает (§4), удалить её можно
вручную.

## 4. Открытие хранилища из папки

«Настройки» → «Хранилище» → «Открыть хранилище из папки…» — сделать каталогом данных существующую
папку с хранилищем Clipensk (например, резервную копию). Текущий каталог данных остаётся на месте и
не удаляется; вернуться к нему можно тем же действием.

**Предусловия:**

- нет незавершённого переноса;
- папка существует, это каталог, не ссылка; не совпадает с текущим каталогом данных, не лежит
  внутри него и не содержит его;
- имя папки не оканчивается на `.incomplete` (незавершённая копия, §3);
- в папке есть хотя бы одна база хранилища; заголовки баз читаются, `storage-crypto.json` прежнего
  формата нет (`ProtectedStorageCredentialState` не `Invalid`);
- в папку можно записывать (пробная запись, как при первом запуске).

**Шаги:**

1. Окно подтверждения: текущий и новый путь; текущее хранилище остаётся на месте; разблокировать
   нужно паролем открываемого хранилища (для копии — паролем на момент её создания); Clipensk будет
   записывать новую историю в эту папку — чтобы сохранить копию нетронутой, откройте её копию.
2. Clipensk блокируется (если разблокирован).
3. Защита доступа папки (непустую папку Clipensk не перенастраивает — исход сообщается).
4. Одна атомарная запись `settings.json`: `DataRootPath` = папка (через `IDataRootLocationStore`,
   перед записью ещё раз проверяется, что marker'а переноса нет).
5. Экран разблокировки нового хранилища. Разблокировка выполняет обычную проверку и восстановление
   (`ProtectedStorageStartupRecoveryCoordinator`), включая доведение незавершённых операций,
   попавших в копию.

Сбой до шага 4 ничего не меняет; запись `settings.json` атомарна.

Подсказка к паролю и выбранный файл перевода — настройки программы (`settings.json`), при открытии
они не меняются. Перевод читается из папки `Languages` открытого хранилища при следующем запуске;
если файла с тем же именем там нет, действует встроенный русский.

## 5. Этапы

1. Этот протокол.
2. Infrastructure: общий код копирования дерева вынесен из движка переноса;
   `DataRootBackupService` (§3), `DataRootOpenService` (§4); тесты на временных каталогах, включая
   отмену, отказы, изменённую копию и незавершённую копию.
3. App: кнопки в «Настройках», подтверждения, прогресс, блокировка; строки локализации.
4. Документы и handoff.

## 6. Что автотестами не подтверждается

- Эксклюзивное открытие файлов — семантика Windows (как у переноса, `DATA_ROOT_RELOCATION_PROTOCOL.md`
  §11); защита доступа папки копии; съёмные и сетевые диски — ручной smoke (`UNVERIFIED`).
- Открытие резервной копии и разблокировка её паролем на production SQLCipher — ручной smoke
  (`UNVERIFIED`); побайтная идентичность копии проверяется автотестами.
